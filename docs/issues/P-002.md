## Initial observations

- **Pattern:** Ongoing; it already fired in runs #70–#71 before this window and fired in all 10 of the reviewed runs (#72–#81), with 0 runs since it last fired. The triage marks the trend "flat" — it is a persistent, not worsening, overshoot.
- **Size:** Newest value 493.3 MB (run #81) against the 320 MB budget, +54.2% over. Across the window it ranged from 455.6 MB (+42.4%) to 576.2 MB (+80.1%).
- **Attribution:** Architectural risk flagged as peak RAM usage with three runtimes resident. No per-screen breakdown was captured for this pass; the data here does not identify which screen drives the peak.
- **Confidence:** High — this fired in every one of the 10 runs reviewed, plus 2 runs before this window. It is a stable, reproducible overshoot, not noise.
- **Next check:** Open Screens > Navigation stack — a high peak on a cheap screen usually means screens held open beneath it, not the screen itself.
